# 웹 디자인 시스템

`packages/community`의 토큰, 컴포넌트, 움직임, 화면 결정을 모은 기준 문서입니다. UI 작업 전에 읽고, 결정이 바뀌면 해당 PR에서 이 문서도 함께 고칩니다.

리디자인(디자인 시스템화와 리브랜딩)은 2026-09-26~27에 시안을 확정하고 `epic/redesign`(#173)에서 진행해 `main`에 머지했습니다. 이 문서는 그 epic의 계획 문서(`docs/redesign.md`)를 이어받았습니다. 아직 옮기지 않은 화면은 `AppShell`의 `REDESIGNED_PATHS` 밖에서 옛 흰 칼럼(`LegacySection`)으로 그려집니다.

- **디자인 캔버스:** https://claude.ai/artifact/Amtiz4SpdRW2rhh5YxZo4S (비공개. 필요한 사람에게 공유해서 봅니다)
- **캔버스의 역할:** 기준 시안입니다. 개발 중 세부가 바뀌어도 캔버스를 매번 고치지는 않고, 컴포넌트 시트에 없는 새 패턴이 생길 때만 추가합니다.
- **모션 실험실:** https://claude.ai/artifact/2qaXo4Qg4ccYfUXy7Wyxkp (비공개). 2장의 움직임 규칙과 8장의 다음 작업을 직접 눌러 비교하는 시안입니다.

## 1. 방향

- **리브랜딩 방향:** "A · Midnight Navy". 기존 navy와 노랑 정체성을 계승하면서 정돈합니다. B(Observatory), C(Deep Field) 안은 참고용으로 캔버스에 남아 있습니다.
- **모바일 우선:** 모바일 비중이 크므로 모바일 레이아웃을 먼저 만들고 데스크톱으로 넓힙니다.
- **내비게이션:** 모바일은 하단 탭바(홈 / 게시판 / 사진 / 장비 / 마이)를 쓰고, 데스크톱은 상단 네비게이션(게시판·사진 드롭다운, 장비 대여, 동아리 소개, 내 메뉴)을 씁니다. 게시판·사진 탭은 그 영역에서 마지막으로 본 게시판으로 가고, 처음이면 첫 공지 게시판과 별사진으로 갑니다. 모바일 전체 메뉴(NavDrawer)를 쓸지는 아직 정하지 않았습니다. 헤더 프로필 메뉴에 있던 로그아웃은 프로필 수정 화면으로 옮깁니다.
- **다크 모드:** 지금 하지는 않지만, 나중에 추가할 수 있도록 컴포넌트는 의미 토큰만 참조합니다.
- **서체:** Pretendard를 씁니다. 시안에는 IBM Plex Sans KR로 대신 그렸습니다.

### 레이아웃 토큰

리디자인 화면을 만들면서 반복된 값을 토큰과 유틸리티로 정리했습니다. 정의는 `src/index.css`에 있고, `cn()`(`~/lib/utils`)도 이 클래스들을 알고 있어서 같은 속성의 다른 클래스와 겹치면 뒤의 것이 이깁니다.

| 클래스 | 값 | 용도 |
| --- | --- | --- |
| `max-w-page` | 1080px | 데스크톱 본문 폭. 상단 네비, 푸터, 모든 리디자인 화면 |
| `pt-safe-N` | max(N × 4px, 위쪽 safe area) | 모바일 상단 바. 보통 `pt-safe-2`(8px), 홈 하늘 헤더는 `pt-safe-3` |
| `pb-safe-N` | max(N × 4px, 아래쪽 safe area) | 시트와 화면 아래 버튼 영역. 보통 `pb-safe-7`(28px) |
| `pb-tab-bar`, `bottom-tab-bar`, `h-tab-bar` | 탭바 높이 + 아래쪽 safe area | 모바일 하단 탭바를 비키거나 그 위에 붙는 요소 |

- **safe area:** `index.html`이 `viewport-fit=cover`라서 화면이 노치 아래까지 그려집니다. 화면 위·아래 끝에 붙는 요소는 위 유틸리티를 쓰고, `env(safe-area-inset-*)`를 직접 쓰지 않습니다. 좌우는 `#root`가 한 번에 비킵니다.
- **탭바 높이:** `--tab-bar-height`(3.5rem)는 `AppShell`이 정합니다. 탭바가 없는 곳(데스크톱)에서는 각 화면이 `md:pb-0`처럼 직접 0으로 돌립니다.

### 관측 모드 (적색광)

`hooks/useObservationMode.ts`가 `<html data-observation="on">`을 켜면 `index.css`의 필터 하나가 모든 화면을 어둡게 뒤집고 빨간빛만 남깁니다. 브랜드 영역(navy)은 뒤집히면 밝은 빨강 띠가 되므로, 관측 모드에서는 브랜드 의미 토큰을 밝은 값으로 바꿔 두어 뒤집힌 뒤 어둡게 나오게 합니다.

- 브랜드 영역(`bg-surface-brand`, `bg-surface-brand-raised`) 위의 글자와 선은 `fg-on-brand`, `fg-on-brand-muted` 같은 의미 토큰을 씁니다. 원시 navy 값을 써야 하면 `index.css`의 관측 모드 블록에 그 값도 뒤집어 둡니다(지금은 navy-200 / 300 / 500 / 700 / 800).
- 사진, 영상, canvas는 먼저 한 번 뒤집어 두어서 음화가 아니라 빨간 밝기로 보입니다.
- 새 화면은 따로 할 일이 없습니다. 브랜드 영역에 새 색을 쓸 때만 관측 모드에서 확인합니다.

### 움직임: 빛으로 나타나고, 빛으로 사라진다

밤하늘에 눈이 적응하듯, 화면 요소는 밝아지고 선명해지면서 나타나고 흐려지면서 사라집니다. 화면 밖에서 미끄러져 들어오거나 커졌다 튕기는 움직임은 쓰지 않습니다. 효과 하나하나는 눈에 띄지 않게 두고, 모든 움직임이 같은 결을 갖는 것으로 분위기를 만듭니다.

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--ease-night` (`ease-night`) | `cubic-bezier(0.22, 1, 0.36, 1)` | 모든 등장과 퇴장. 길게 감속하는 곡선 하나만 씁니다 |
| `--duration-quick` | 240ms | hover, 눌림, 탭 글자색, 드롭다운 메뉴 |
| `--duration-base` | 450ms | 다이얼로그, 탭 내용, 페이지 이동, NavDrawer |
| `--duration-slow` | 900ms | 토스트, 사진 상세 |

- **등장:** opacity 0→1, blur 8→0px, brightness 0.6→1. 위치 이동이 필요하면 24px 이하로만 합니다.
- **퇴장:** opacity 1→0, blur 0→4px. 등장 길이의 60%로 짧게 합니다.
- **클래스:** 트랜지션은 `transition-colors duration-(--duration-quick) ease-night`처럼 씁니다. 애니메이션은 아래 클래스를 씁니다(`src/index.css`).

| 클래스 | 쓰는 곳 |
| --- | --- |
| `animate-light-in` / `animate-light-out` | Dialog, ConfirmDialog의 본문(`data-[state=open]` / `data-[state=closed]`), Sheet 안의 내용, 바뀌는 탭 내용(`key`로 다시 그려서 재생) |
| `animate-overlay-in` / `animate-overlay-out` | 다이얼로그 뒤의 어두운 막 |
| `animate-toast-in` | Toast. 들어올 때 노란 별빛 테두리가 한 번 번졌다가 사라집니다 |
| `animate-breathe` | Skeleton. 빠른 pulse 대신 2.4초 주기로 천천히 숨 쉽니다 |
| `animate-fade-in/out` | 드롭다운 메뉴, NavDrawer의 막 |
| `animate-slide-in/out-left` | NavDrawer |
| `animate-accordion-down/up` | NavDrawer의 그룹 |
| `animate-twinkle` | 하늘 헤더의 별. 별마다 `--star-opacity`와 길이를 따로 줍니다 |

- **페이지 이동:** `router.tsx`가 경로가 바뀔 때만 View Transitions API로 `page` 전환을 겁니다. 옛 화면은 흐려지며 사라지고 새 화면이 선명해지며 나타나고, 상단 네비(`top-nav`)와 탭바(`tab-bar`)는 제자리에 있습니다. `?photo=<id>`처럼 search param만 바뀌는 이동에는 걸지 않습니다. 전환 타입을 지원하지 않는 브라우저와 관측 모드에서는 바로 바뀝니다.
- **예외:** 화면 가장자리에 붙어 손가락을 따라가는 요소는 미끄러짐을 유지합니다. 하단 시트(vaul)는 끌어서 닫을 수 있어서 시트 자체는 미끄러지고, 그 안의 내용만 `animate-light-in`을 따릅니다. NavDrawer도 왼쪽에서 열리되 곡선은 `ease-night`를 씁니다.
- **동작 줄이기:** 애니메이션과 트랜지션에는 `motion-reduce:animate-none`이나 `motion-reduce:transition-none`을 함께 붙여서 `prefers-reduced-motion`을 따릅니다. 퇴장 애니메이션 끝에 숨기는 요소는 `motion-reduce:hidden`으로 바로 숨깁니다(Toast). 페이지 전환도 꺼집니다.
- **관측 모드:** blur와 brightness는 관측 모드 필터와 겹쳐도 어둡게 남습니다. 새로 노란빛(accent)을 번지게 하는 효과를 넣을 때는 관측 모드에서 확인합니다.

## 3. 기본 컴포넌트

shadcn/ui 방식을 씁니다. headless 라이브러리 위에 `cva`와 `tailwind-merge`를 얹고, 코드를 저장소 안에 둡니다. 위치는 `src/components/ui/`이고 `~/components/ui`에서 가져옵니다.

- **라이브러리:** Radix(Dialog, Tabs, ToggleGroup, Avatar, Slot), 하단 시트는 vaul, 아이콘은 lucide-react를 씁니다. remixicon은 화면 PR마다 lucide로 바꿔 나갑니다.
- **클래스 합치기:** `~/lib/utils`의 `cn()`을 씁니다. 타이포 토큰(`text-label` 등)을 글자 크기로 인식하도록 설정해 두었습니다.

## 5. 확정된 결정 사항

- **홈:** 소리통, 새 글, 새 사진(별사진), 새 앨범(추억 만들기) 순서로 놓고, 오늘 밤을 더합니다. 새 댓글, 사진전, 바로가기, 장비 대여는 홈에 두지 않습니다(장비 대여 등 기능은 상단 메뉴 그룹으로 모을 예정). 데스크톱은 상단 남색 밴드에 소리통과 오늘 밤을 나란히 두고, 그 아래 새 글과 새 사진을 같은 크기의 카드로 나란히, 새 앨범을 4장 한 줄로 둡니다(캔버스 `HomeDesktop`). 오늘 밤에는 옛 홈의 월령 그림(노란 달)을 `MoonPhase` SVG로 살려 둡니다.
- **소개 페이지:** 커뮤니티에서 뺍니다(`/about/*`). 나중에 동아리 공개 사이트(snuaaa-home, `https://www.snuaaa.net`)에 합치고, 커뮤니티에는 데스크톱 상단 네비와 모바일 홈 헤더에 '동아리 소개' 외부 링크만 둡니다. AAArchive는 '옛 홈페이지'로 이름을 바꿔, 동아리 소개와 함께 사이트 푸터에 둡니다. 푸터는 데스크톱은 모든 화면에, 모바일은 홈 맨 아래에만 보입니다.
- **로그아웃(임시):** 로그아웃을 프로필 수정 화면으로 옮기기 전까지 모바일은 마이 탭 아래, 데스크톱은 내 메뉴에 둡니다.
- **menu 0 게시판 제거:** 모임게시판, 시그너스, 손님방을 메뉴에서 없앱니다. 단, 손님방은 가입 안내 문구와 얽혀 있습니다(7장 참고).
- **`category_color` 사용 안 함:** 카테고리는 색 없이 칩으로 보여줍니다.
- **이메일 비공개:** 다른 회원의 유저페이지에서는 이메일을 숨깁니다. 학번과 전공만 보여줍니다.
- **회기 표기:** "93대"처럼 씁니다.
- **앨범 종류:**
  - 그룹 앨범: 앨범 안에 누구나 사진을 올릴 수 있습니다.
  - 개인 앨범: 앨범을 만든 사람만 올릴 수 있습니다.
- **글 상세:** 이전 글 / 다음 글은 두지 않습니다.
- **댓글:** 추천한 사람 목록은 보여주지 않고 숫자만 보여줍니다.
- **에디터 툴바:** 지금 `Editor.tsx`의 CKEditor 툴바 항목을 그대로 유지합니다. 모바일에서는 키보드 위에 붙이고 가로로 스크롤합니다.
- **EXIF 자동 입력:** 나중에 추가합니다.

## 6. API · 로직 변경이 필요한 UX 변경

리디자인 중에 정리한 목록입니다. 화면 PR과 섞지 않고 별도 PR로 진행합니다. API 변경은 지금 배포된 웹을 깨지 않도록 하위 호환으로 넣습니다(`CLAUDE.md` 참고).

- **사진 넘기기 (A 방식):** 사진을 연 목록 안에서 넘깁니다.
  - 기준: 앨범에서 열면 앨범 안, 별사진 목록에서 열면 게시판 전체(적용된 태그 필터 유지), 유저페이지에서 열면 그 유저의 사진 안입니다.
  - 구현: 목록 쿼리 캐시에 있는 사진 ID 순서를 씁니다. 맥락은 `?photo=<id>&photoCtx=<album:id | board:id | user:uuid>`처럼 search param으로 넘깁니다.
  - 링크로 바로 들어온 경우: 앨범이 있으면 앨범, 없으면 게시판을 기준으로 넘깁니다.
  - 앨범 경계: 마지막 사진에서 멈추고 "다음 앨범" 버튼을 따로 보여주는 방식이 제안 상태입니다.
  - 현재 구현: 서버가 `prevPhoto` / `nextPhoto` / `prevAlbumPhoto` / `nextAlbumPhoto`로 이전·다음을 정합니다. #162에서 유저 기준 이동이 서버 방식으로 먼저 들어갔습니다. 유저페이지에서 열면 `?photoNavigation=user`가 붙고, API는 `navigation=user`일 때 작성자 기준으로 이전·다음을 계산합니다.
  - #162는 임시 수정입니다. A 방식으로 옮길 때 서버 계산 로직(`navigation=user`)을 포함해 자유롭게 바꿔도 됩니다. search param 이름은 기존 `photoNavigation`을 넓혀 쓰는 것(`album` / `board` / `user`)을 기본으로 합니다.
- **게시판 목록 무한 스크롤 (모바일):** `usePostList`를 `useInfiniteQuery`로 바꿉니다. API는 이미 offset과 limit을 받습니다.
- **앨범 생성 후 흐름:** 모달을 닫는 대신 새로 만든 앨범의 상세(사진 목록) 화면으로 이동합니다.
- **장비 대여:** 한 개씩 빌리기와 일괄 대여를 합쳐, 담아서 한 번에 빌리는 흐름 하나로 만듭니다. 확인은 `window.confirm` 대신 ConfirmDialog로 하고, 반납 기한을 크게 보여줍니다.
- **alert, confirm을 인라인 처리로 바꾸기:** 필수 항목이 비면 제출 버튼을 막고 문구로 알려줍니다. 적용 대상은 문서 등록, 반납 사진, 사진 업로드 대기, 회원가입 검증 등입니다.
- **임시저장 안내:** 글쓰기에서 저장된 글을 말없이 불러오는 대신 "이어서 쓰기 / 새로 쓰기" 배너를 보여줍니다.
- **촬영 정보 일괄 적용:** 사진 올리기에서 촬영 정보를 선택한 사진 모두에 한 번에 적용합니다.
- **게시판 전환:** 모바일 헤더의 게시판 이름을 누르면 전환 시트가 열립니다. `lv_write`가 부족한 게시판은 "읽기 전용"으로 표시하고 글쓰기 버튼을 숨깁니다.

## 7. 발견한 문제 · 열린 질문

- **카테고리 필터:** `components/Board/PostBoard/List.tsx`의 카테고리 `<select>`에 `onChange`가 없어서 선택해도 아무 일이 일어나지 않습니다. 지금은 카테고리가 있는 게시판이 없어서 문제가 드러나지 않습니다. 게시판 PR에서 새로 만들면서 필터 동작을 넣습니다.
- **손님방과 가입 안내:** 회원가입 안내문은 9등급 회원에게 손님방에 문의하라고 안내합니다. 손님방을 없애기 전에 이 문구를 바꿔야 합니다. 시안에서는 snuaaa@gmail.com 문의로 대체했습니다. 문구만 바뀌더라도 menu 0 게시판을 정리하는 PR에서 함께 바꿉니다.
- **목록 API의 썸네일 · 첨부 여부:** 지금은 주지 않습니다. `retrievePostsInBoard`(`api/src/controllers/post.controller.ts`)는 `post`와 작성자 `nickname`만 포함합니다. 시안의 목록 썸네일과 첨부 아이콘을 위해 게시판 PR 전에 `main`에 필드를 추가해야 합니다.
- **태그 필터 조건:** 지금은 OR입니다(`tag_id IN (...)`). 이 동작을 유지합니다.
- **장비 분류 이름:** 시안의 분류 이름(망원경, 가대 등)은 예시입니다. 실제 값은 API에서 받습니다.
- **디자인하지 않은 화면:** 관리자 화면(장비 관리, 연체료, 회원 관리), 비밀번호 변경 화면은 기존 컴포넌트를 조합해 개발하면서 만듭니다.
