# 웹 리디자인 · 디자인 시스템 계획

`packages/community`의 UI를 디자인 시스템화하고 리브랜딩하는 작업의 기준 문서입니다. 디자인 시안은 2026-09-26~27에 확정했고, 세부 사항은 개발하면서 다듬습니다. 결정이 바뀌면 해당 PR에서 이 문서도 함께 수정합니다.

- **디자인 캔버스:** https://claude.ai/artifact/Amtiz4SpdRW2rhh5YxZo4S (비공개. 필요한 사람에게 공유해서 봅니다)
- **캔버스의 역할:** 기준 시안입니다. 개발 중 세부가 바뀌어도 캔버스를 매번 고치지는 않고, 컴포넌트 시트에 없는 새 패턴이 생길 때만 추가합니다.

## 1. 방향

- **리브랜딩 방향:** "A · Midnight Navy". 기존 navy와 노랑 정체성을 계승하면서 정돈합니다. B(Observatory), C(Deep Field) 안은 참고용으로 캔버스에 남아 있습니다.
- **모바일 우선:** 모바일 비중이 크므로 모바일 레이아웃을 먼저 만들고 데스크톱으로 넓힙니다.
- **내비게이션:** 모바일은 하단 탭바(홈 / 게시판 / 사진 / 장비 / 마이)를 쓰고, 데스크톱은 상단 네비게이션을 씁니다. 헤더 프로필 메뉴에 있던 로그아웃은 프로필 수정 화면으로 옮깁니다.
- **다크 모드:** 지금 하지는 않지만, 나중에 추가할 수 있도록 컴포넌트는 의미 토큰만 참조합니다.
- **서체:** Pretendard를 씁니다. 시안에는 IBM Plex Sans KR로 대신 그렸습니다.

## 5. 확정된 결정 사항

- **menu 0 게시판 제거:** 모임게시판, 시그너스, 손님방을 메뉴에서 없앱니다. 단, 손님방은 가입 안내 문구와 얽혀 있습니다(7장 참고).
- **`category_color` 사용 안 함:** 카테고리는 색 없이 칩으로 보여줍니다.
- **이메일 비공개:** 다른 회원의 유저페이지에서는 이메일을 숨깁니다. 학번과 전공만 보여줍니다.
- **회기 표기:** "93대"처럼 씁니다.
- **앨범 종류:**
  - 그룹 앨범: 앨범 안에 누구나 사진을 올릴 수 있습니다.
  - 개인 앨범: 앨범을 만든 사람만 올릴 수 있습니다.
- **글 상세:** 이전 글 / 다음 글은 두지 않습니다.
- **댓글:** 추천한 사람 목록은 보여주지 않고 숫자만 보여줍니다.
- **에디터 툴바:** 지금 `Editor.tsx`의 CKEditor 툴바 항목을 그대로 유지합니다. 모바일에서는 키보드 위에 붙이고 가로로 스크롤합니다.
- **EXIF 자동 입력:** 나중에 추가합니다.

## 6. API · 로직 변경이 필요한 UX 변경

화면 PR과 섞지 않고 별도 이슈나 PR로 진행합니다.

- **사진 넘기기 (A 방식):** 사진을 연 목록 안에서 넘깁니다.
  - 기준: 앨범에서 열면 앨범 안, 별사진 목록에서 열면 게시판 전체(적용된 태그 필터 유지), 유저페이지에서 열면 그 유저의 사진 안입니다.
  - 구현: 목록 쿼리 캐시에 있는 사진 ID 순서를 씁니다. 맥락은 `?photo=<id>&photoCtx=<album:id | board:id | user:uuid>`처럼 search param으로 넘깁니다.
  - 링크로 바로 들어온 경우: 앨범이 있으면 앨범, 없으면 게시판을 기준으로 넘깁니다.
  - 앨범 경계: 마지막 사진에서 멈추고 "다음 앨범" 버튼을 따로 보여주는 방식이 제안 상태입니다.
  - 현재 구현: 서버가 `prevPhoto` / `nextPhoto` / `prevAlbumPhoto` / `nextAlbumPhoto`로 이전·다음을 정합니다. #162에서 유저 기준 이동이 서버 방식으로 먼저 들어갔습니다. 유저페이지에서 열면 `?photoNavigation=user`가 붙고, API는 `navigation=user`일 때 작성자 기준으로 이전·다음을 계산합니다.
  - #162는 임시 수정입니다. A 방식으로 옮길 때 서버 계산 로직(`navigation=user`)을 포함해 자유롭게 바꿔도 됩니다. search param 이름은 기존 `photoNavigation`을 넓혀 쓰는 것(`album` / `board` / `user`)을 기본으로 합니다.
- **게시판 목록 무한 스크롤 (모바일):** `usePostList`를 `useInfiniteQuery`로 바꿉니다. API는 이미 offset과 limit을 받습니다.
- **앨범 생성 후 흐름:** 모달을 닫는 대신 새로 만든 앨범의 상세(사진 목록) 화면으로 이동합니다.
- **장비 대여:** 한 개씩 빌리기와 일괄 대여를 합쳐, 담아서 한 번에 빌리는 흐름 하나로 만듭니다. 확인은 `window.confirm` 대신 확인 시트로 하고, 반납 기한을 크게 보여줍니다.
- **alert, confirm을 인라인 처리로 바꾸기:** 필수 항목이 비면 제출 버튼을 막고 문구로 알려줍니다. 적용 대상은 문서 등록, 반납 사진, 사진 업로드 대기, 회원가입 검증 등입니다.
- **임시저장 안내:** 글쓰기에서 저장된 글을 말없이 불러오는 대신 "이어서 쓰기 / 새로 쓰기" 배너를 보여줍니다.
- **촬영 정보 일괄 적용:** 사진 올리기에서 촬영 정보를 선택한 사진 모두에 한 번에 적용합니다.
- **게시판 전환:** 모바일 헤더의 게시판 이름을 누르면 전환 시트가 열립니다. `lv_write`가 부족한 게시판은 "읽기 전용"으로 표시하고 글쓰기 버튼을 숨깁니다.

## 7. 발견한 문제 · 열린 질문

- **버그:** `components/Board/PostBoard/List.tsx`의 카테고리 `<select>`에 `onChange`가 없어서 선택해도 아무 일이 일어나지 않습니다.
- **손님방과 가입 안내:** 회원가입 안내문은 9등급 회원에게 손님방에 문의하라고 안내합니다. 손님방을 없애기 전에 이 문구를 바꿔야 합니다. 시안에서는 snuaaa@gmail.com 문의로 대체했습니다.
- **목록 API 확인:** 게시판 목록 API가 썸네일과 첨부파일 여부를 주는지 확인해야 합니다. 시안의 목록 썸네일과 첨부 아이콘이 여기에 달려 있습니다.
- **태그 필터 조건:** 별사진 태그를 여러 개 고를 때 AND인지 OR인지 확인해야 합니다.
- **장비 분류 이름:** 시안의 분류 이름(망원경, 가대 등)은 예시입니다. 실제 값은 API에서 받습니다.
- **디자인하지 않은 화면:** 관리자 화면(장비 관리, 연체료, 회원 관리), 비밀번호 변경 화면, 소개 페이지는 기존 컴포넌트를 조합해 개발하면서 만듭니다.

## 8. 브랜치 전략

리디자인은 epic 브랜치 `epic/redesign`에서 진행합니다. 프로덕션은 `main`에서 만든 `WEB-*` 태그로 배포되므로, 일부만 옮긴 UI가 버그 수정 릴리스에 섞여 나가지 않게 하기 위해서입니다.

- **하위 브랜치:** 작업마다 `epic/redesign`에서 `feat/redesign-tokens`처럼 브랜치를 만들고, `epic/redesign`을 대상으로 PR을 올립니다. 하위 PR은 squash 머지합니다.
- **main 따라가기:** 주기적으로 `main`을 `epic/redesign`에 merge합니다. 여러 사람이 쓰는 브랜치라 rebase하지 않습니다.
- **충돌 줄이기:** 리디자인 기간에는 `main`에서 UI 파일 수정을 최소화합니다.
- **API 변경:** 웹과 따로 배포할 수 있는 API 변경은 `main`으로 바로 보냅니다. API는 `API-*` 태그로 따로 배포됩니다.
- **최종 머지:** `epic/redesign`에서 `main`으로는 merge commit으로 합칩니다. 화면 단위 커밋 기록을 남기기 위해서입니다.
- **CI와 프리뷰:** epic 대상 PR의 CI와 epic 프리뷰 배포는 별도 PR로 `main`의 워크플로에 추가하고, 머지되면 epic에 반영합니다. 그 전까지 하위 PR은 로컬에서 `lint`, `typecheck`, `build`로 확인합니다.

## 9. PR 순서

각 PR에서 옮긴 화면의 SCSS를 함께 지웁니다. 진행 상황은 남은 SCSS 줄 수로 확인합니다.

1. **토큰:** `@theme`에 원시·의미 토큰과 등급 그라데이션을 정의하고, 코드 곳곳의 hex 값과 Tailwind 기본 팔레트를 토큰으로 바꿉니다. 이 PR에서는 UI가 거의 바뀌지 않아야 합니다.
2. **기본 컴포넌트:** Button, Input, Tag, Avatar, BottomSheet / Dialog, Tabs를 만듭니다.
3. **레이아웃:** 모바일 하단 탭바와 데스크톱 상단 네비게이션을 만듭니다(`routes/__root.tsx`).
4. **게시판:** 목록(N, D), 게시판 전환, 검색, 글 상세와 댓글을 옮깁니다.
5. **사진:** 사진 탭(A, M, E), 필터, 사진 상세, 앨범 상세를 옮깁니다.
6. **작성 화면:** 글쓰기, 사진 올리기, 문서 등록, 앨범 만들기를 옮깁니다.
7. **사용자:** 마이페이지, 유저페이지, 프로필 수정을 옮깁니다.
8. **장비 대여**를 옮깁니다.
9. **로그인 · 회원가입**을 옮깁니다.

6장의 UX 변경은 해당 화면 PR의 앞이나 뒤에 별도 PR로 진행합니다.
